# 연도별 교과과정과 졸업요건 설계

## 상태와 목적

검토 후 구현 기준으로 확정한 설계입니다. 실행된 DB 변경이나 현재 API 동작을 설명하는 문서가 아닙니다.
학생은 입력한 수강 연도의 교과과정에 포함된 과목만 선택해야 합니다. 졸업요건은 수강 연도가 아니라 입학연도, 전공 유형, 다중전공 합격 시점과 공식 경과조치에 따라 판정합니다.
구현은 아래 작업 단위 순서로 나누며, 계획 검토 후 기존 체크아웃에서 단독으로 진행합니다. 새 워크트리나 서브에이전트는 사용하지 않습니다.

## 근거 자료

- 사용자 제공 `2024_소융_교과과정표.xlsx`, `2025_소융_교과과정표.xlsx`, `2026_소융_교과과정표.xlsx`.
- 사용자 제공 `소프트웨어융합공학과 졸업을 위한 필수 이수 교과목 안내.hwp`의 1~7항.
- 현재 `Course`, `StudentGrade`, `StudentMajor`, `GraduationRequirement`, `RequiredCourse`와 관련 서비스.
- 각 저장소의 `AGENTS.md`, 백엔드 `docs/domain/index.md`, `docs/api/README.md`.

원본은 변경하지 않습니다. 문서에 적힌 교과과정 연도와 입학연도는 동일한 뜻으로 취급하지 않습니다. 학수번호 오류나 자료에 없는 학점을 추정해 운영 DB에 입력하지 않습니다.

자료 누락은 최신 연도 정책으로 대체하거나 졸업 충족으로 처리하지 않습니다.

## 작업 단위 A: 연도별 과목 선택

### 데이터 모델

```text
department ──< curriculum ──< curriculum_course >── course
                                                     │
                                                student_grade
```

`course`의 기존 ID, 외부 entityId, 학수번호 유일성, 성적 FK는 유지합니다. 동일 이름·다른 학수번호의 과목은 합치지 않습니다.

| 테이블 | 컬럼 |
| --- | --- |
| curriculum | id bigint identity PK, entity_id UUID UNIQUE, department_id FK NOT NULL, curriculum_year integer NOT NULL, source_title varchar(200) NOT NULL, source_url varchar(2048) nullable, published boolean NOT NULL DEFAULT false, created_at/updated_at timestamptz |
| curriculum_course | id bigint identity PK, entity_id UUID UNIQUE, curriculum_id FK NOT NULL, course_id FK NOT NULL, division varchar(30) NOT NULL, recommended_year integer nullable, recommended_term varchar(20) nullable, area_code varchar(30) nullable, area_name varchar(100) nullable, major_area varchar(100) nullable, note text nullable, created_at/updated_at timestamptz |

- `UNIQUE(department_id, curriculum_year)`와 `UNIQUE(curriculum_id, course_id)`를 적용합니다.
- curriculum에는 편집 충돌 검사용 version bigint NOT NULL DEFAULT 0을 추가합니다. 관리자 수정·공개 요청은 조회한 version을 제출하며 불일치는 409 CURRICULUM_EDIT_CONFLICT입니다.
- division은 `MAJOR_REQUIRED`, `MAJOR_ELECTIVE`, `MAJOR_FOUNDATION`, `GENERAL_REQUIRED`, `GENERAL_ELECTIVE`, `ELECTIVE` 중 하나입니다.
- 기록 시간은 기존 Instant/timestamptz, 학점은 BigDecimal/numeric 규약을 유지합니다.
- 권장 학년은 1~6, 권장 학기는 FIRST/SECOND/BOTH이며 미지정은 null입니다. 권장 정보를 실제 수강 가능 학기 제한으로 사용하지 않습니다.
- 연도 범위는 2000~9999입니다. 연도, 출처, 문자열 길이는 API와 엔티티에서 검증합니다.
- FK는 RESTRICT/NO ACTION으로 설정합니다. 교과과정 변경으로 기존 성적을 cascade delete하지 않습니다.
- UNIQUE와 PK가 제공하는 인덱스를 중복 생성하지 않습니다. 추가 인덱스, Redis, JPA 2차 캐시, 파티셔닝은 도입하지 않습니다.
- 2026-10-07 승인된 보안 후속 작업: 신규 curriculum/curriculum_course에 RLS를 활성화하고 직접 클라이언트용 허용 정책을 추가하지 않습니다. 학생·관리자 클라이언트는 Spring API를 사용합니다. JDBC 역할의 실제 접근을 확인하며 기존 테이블 권한·RLS는 변경하지 않습니다.

### 저장과 공개

- 관리자가 학과, 연도, 출처와 전체 과목 연결을 초안으로 저장합니다.
- 저장된 학과·연도는 편집으로 변경하지 않습니다. 다른 학과·연도 자료는 새로 생성합니다.
- 내용 교체는 트랜잭션으로 처리합니다. 존재하지 않는 과목, 중복 연결, 잘못된 분류가 하나라도 있으면 전체 요청을 거절합니다.
- 후보 과목을 일괄 조회하고 연결 생성 동안 공유 잠금을 유지합니다. 과목 수정은 배타 잠금으로 처리하며 교과과정에 연결된 과목의 학과·분류 변경을 거절합니다. 목록도 연결을 일괄 조회하여 N+1을 피합니다.
- 공개된 내용을 수정하면 초안으로 돌아갑니다. 편집/공개 변경과 성적 등록은 같은 curriculum 행을 잠가 검증과 저장의 순서를 보장합니다.
- 편집/공개 변경은 배타 잠금, 성적 연결 검증은 공유 잠금을 사용합니다. 검증 시 같은 연도의 행을 ID순으로 잠그고 공개 여부를 잠금 후 다시 확인합니다.
- 분류와 권장 학기 enum은 DTO·엔티티가 함께 쓰는 domain 패키지에 둡니다. 비고는 4000자, 한 요청의 과목 연결은 2000개까지 허용합니다.
- 빈 교과과정은 공개할 수 없습니다. 관리자가 출처와 자료 완비를 확인하여 공개하며, 서버는 자료에 없는 과목을 보충하지 않습니다.
- 연도별 목록에서 제외된 것을 course 전체 비활성화로 처리하지 않습니다. 비활성 과거 과목은 관리자가 공식 자료를 확인해 연결한 공개 교과과정에 한해서 과거 연도 성적 입력에 사용할 수 있습니다.
- 일반 과목 관리 API의 비활성 정책은 유지합니다. 성적 선택은 현재 is_active만이 아니라 공개된 연도별 연결을 기준으로 판단합니다.
- 같은 학수번호의 이름이나 학점이 기존 값과 다르면 자동 덮어쓰기를 거절합니다. 연도별 이름·학점 이력 모델은 실제 차이에 대한 공식 확인 후 별도로 설계합니다.

### API 계약

- `GET /api/v1/curriculum-courses?academicYear=2024&departmentEntityId=<UUID>`: 인증 필수, academicYear 필수, 학과 필터 선택. 해당 연도의 공개 교과과정에 포함된 과목만 course.entityId로 중복 제거하여 code 오름차순으로 반환합니다.
- 응답은 기존 CourseResponse 배열입니다. 권장 학년·학기로 제한하지 않습니다. 학과 필터는 course.department가 아니라 curriculum.department에 적용합니다.
- 해당 교과과정이 없으면 `404 CURRICULUM_NOT_AVAILABLE`입니다. 초안 내용은 학생에게 노출하지 않으며 다른 연도로 대체하지 않습니다.
- 기존 `GET /api/v1/courses`는 관리자 후보 검색과의 호환성을 유지하되 성적 등록 후보 조회에는 사용하지 않습니다.
- 관리자 API: `GET/POST /api/v1/admin/curricula`, `GET/PUT /api/v1/admin/curricula/{entityId}`, `PUT /api/v1/admin/curricula/{entityId}/publication`. 모든 작업에서 기존 AdminAccessService 권한 검증을 재사용합니다.
- 기존 `POST /api/v1/grades`는 academicYear와 courseEntityId의 공개 연결을 검증합니다. RPL에도 임의의 예외를 추가하지 않습니다.
- 성적의 수강 연도를 변경하면 다시 검증합니다. 연도를 유지한 채 등급 등을 수정할 때는 연결 누락만을 이유로 기존 성적 수정을 막지 않습니다.
- 잘못된 연결은 `400 COURSE_NOT_IN_CURRICULUM`, 교과과정 미등록/미공개는 `404 CURRICULUM_NOT_AVAILABLE`, 관리자 중복 연도는 `409 CURRICULUM_ALREADY_EXISTS`입니다.
- 기존 ApiErrorResponse 형태와 401/403 정책을 유지합니다. 학생 소유자는 JWT subject에서 결정합니다.

### 모바일과 관리자 화면

- 성적 입력은 수강 연도, 학기, 과목, 학점·성적 순서입니다. 연도를 바꾸면 과목, 검색어, 과목에서 자동 입력한 학점, 재수강 후보를 초기화합니다.
- 조회 중 과목 선택과 등록을 막습니다. 연도 변경 전 요청의 늦은 응답은 generation 검사로 무시합니다.
- 자료가 없는 연도는 '이 연도의 교과과정이 아직 등록되지 않았어요.'로 안내하고 다른 연도 과목을 섞지 않습니다.
- 기존 과목은 성적 수정 화면에서 이력으로 표시합니다. 연도 변경으로 불일치하면 저장을 막고, 과목 변경을 지원하지 않는 기존 수정 API에서는 새로 등록하도록 안내합니다.
- 관리자는 학과·연도별 목록, 출처, 초안 편집, 공개/비공개를 관리합니다. 과목 후보에는 기존 과목 검색을 재사용합니다.
- AHNI의 기존 색상, 폰트, 크기, WhitespaceWrappedText, 접근성과 loading/empty/error/retry 규칙을 유지합니다. 시뮬레이터·실기기 테스트는 사용자가 수행합니다.

### 기존 데이터와 적용

- 새 테이블을 추가하며 기존 과목·성적에 연도를 추측한 일괄 보정은 하지 않습니다.
- 엑셀의 67개 학수번호, 149개 연도별 연결을 대조 기준으로 사용합니다. 교양 누락은 임의로 보충하지 않습니다.
- 공식 데이터 입력은 스키마 구현·테스트와 별도 작업입니다. 구현 검증에서 공유 Supabase나 ahni_dev의 기존 행을 수정하지 않습니다.
- 교과과정 공개 전에는 새 연도별 성적 등록이 불가능합니다. 기존 전체 목록으로 우회하지 않습니다.
- Flyway SQL과 JPA를 함께 변경합니다. dev의 ddl-auto=update가 모든 CHECK 제약을 반영한다고 가정하지 않습니다. 기존 로컬 데이터를 삭제하지 않고 필요한 차분 SQL과 적용 순서를 구현 문서에 남깁니다.

## 작업 단위 B: 다중전공 기준 시점

- student_major에 합격 연도·학기를 추가합니다. created_at은 앱 등록 시각이므로 대신 사용하지 않습니다.
- PRIMARY는 입학연도, DOUBLE_MAJOR/MINOR의 필수과목 교과과정은 실제 합격 연도·학기, 학점 기준은 입학연도에서 각각 해결합니다.
- 기존 합격 시점은 nullable로 추가하고 추측하여 보정하지 않습니다. 미입력은 보완 입력 상태로 안내하며 입학연도로 암묵 대체하지 않습니다.
- 프로필 API, 모바일 전공 입력, 관리자 요건 입력, OpenAPI, 단위·통합 테스트를 같은 작업에서 변경합니다.
- 복수·부전공에 따라 변하는 주전공 학점은 일반 PRIMARY의 65학점을 모두에게 적용하지 않고 전공 구성별 공식 기준으로 처리합니다. 둘 다 있는 경우의 주전공 기준은 공식 확인 전 판정하지 않습니다.

## 작업 단위 C: 선택·대체·경과조치

- 기존 required_course는 개별 필수과목용으로 유지합니다. 영어는 후보 3과목 중 1과목·3학점 그룹, 핵심교양은 A/B 경로 중 하나로 4과목·12학점을 충족하는 그룹으로 추가합니다.
- 후보는 학수번호가 확인된 course와 FK로 연결합니다. 같은 과목을 한 그룹에서 중복 집계하지 않으며 자료가 불완전한 그룹은 공개하지 않습니다.
- GED 영역은 과목명 문자열이 아니라 공식 area_code로 평가합니다. A/B 혼합은 인정하지 않습니다.
- 중점·기초·계열·핵심교양의 최소학점을 교양 총학점과 구분합니다. 2025 이후 전공기초 15학점은 전공 65학점과의 관계 확인 후 학점 기준을 확정합니다.
- 대체 관계에는 원 과목, 대체 과목, 적용 입학연도 범위, 시행 연도·학기, 출처, 필수 이수/재수강 인정 목적을 저장합니다. 이름이 같다는 이유로 인정하지 않습니다.
- 대체 관계 추가로 기존 성적은 바뀌지 않습니다. GPA 재수강 처리는 사용자 지정 replaced_grade와 공식 재수강 관계의 조건 검증을 유지합니다.
- 대체 관계를 무제한으로 연결하여 추론하지 않습니다. 공식 확인된 조건부 관계만 사용하고 자기 연결, 순환, 중복 인정을 거절합니다.
- 면제는 공식 경과조치로 관리합니다. 연도별 목록에서 빠졌다는 사실만으로 면제하지 않으며, 복학·재입학 이력이 확인되지 않은 학생에게 관련 예외를 자동 적용하지 않습니다.
- 선택 그룹과 대체 관계의 세부 스키마/API는 독립 작업 시작 전에 설계와 테스트 사례를 확정합니다. 작업 A에 미래용 빈 테이블은 만들지 않습니다.

## 구현 순서와 완료 기준

1. A의 새 테이블·제약과 기존 데이터 보존 테스트.
2. A의 관리자 초안/공개 API, 연도별 조회, 성적 저장 검증.
3. A의 모바일·관리자 화면과 계약 갱신, 전체 하네스 검증.
4. B의 합격 시점 입력과 기준 연도 분리.
5. C의 영어 선택과 핵심교양 경로 판정.
6. C의 공식 확인된 대체 관계, 학점 내역, 경과조치.

각 구현 단위는 전용 feat 브랜치에서 진행하며 RED→GREEN, 관련 API 문서, 각 프로젝트 scripts/verify를 포함합니다. 공유 DB 적용, push, merge는 별도 작업입니다.
과거 성적 보존, 다른 연도 후보 제외, 미확인 조건의 암묵 적용 금지, 공개 권한 검증, 학점 중복 집계 방지가 우선 수용 기준입니다.
